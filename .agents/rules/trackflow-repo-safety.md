# Rule: TrackFlow Repo Safety

- Scope: always-active

## Purpose

Keep TrackFlow delivery aligned with the company context and avoid accidental regressions across milestones.

## Rule

1. Read `CONTEXT.md` and the memory bank before editing code.
2. Reuse code from existing TrackFlow modules before creating new logic.
3. Treat `apps/trackflow-coding-fundamentals/src/` as the source of truth for Milestone 2 business logic.
4. Do not edit `apps/talent-pipeline-tracker/` while working on TrackFlow unless the developer explicitly asks for that app.
5. Update `memory-bank/progress.md` whenever a new architecture decision or milestone artifact is added.
